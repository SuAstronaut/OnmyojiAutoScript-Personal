# 账号数据导出（单账号 / 多账号）

OAS 可以直接导出 YYX 格式的账号快照，不需要运行或保留 `yyx-bridge` 项目。OAS 只生成数据文件，不提供账号数据展示页面。

## 使用条件

- MuMu 12，当前游戏进程为 x86_64，开启模拟器 root。
- OAS 已配置并能连接对应的 ADB 设备。
- 桥接模式使用局域网 `IP:端口`；非桥接模式使用 `127.0.0.1:端口` 或模拟器设备序列号。导出复用 OAS 的连接地址，无需额外配置桥接开关。
- 目前不支持官方 Windows 桌面客户端、ARM64 游戏进程或无 root 的模拟器。

## 首次安装

在 OAS 根目录运行一次：

```powershell
.\toolkit\python.exe -m dev_tools.yyx_export --install
```

这会下载并校验固定版本的官方 Frida 设备端组件，保存在 `toolkit/yyx_export/`。Python 依赖已列入项目现有 requirements；不要改用系统 Python。

## 单账号任务

在 OAS 任务菜单中选择「账号数据导出」，启用任务并设置下次运行时间。它导出当前 OAS 设备上已登录的角色，不切换账号。默认关闭；成功间隔为一天，普通失败间隔为两小时，可在该任务的调度器中调整。

## 批量导出

1. 打开「多账号通用任务 → 多账号通用配置」。
2. 将「执行的任务」选为「账号数据导出」。
3. 选择账号来源方式，并按原有方式配置需要导出的小号。
4. 启用「多账号通用任务」并设置其下次运行时间。

批量任务会在当前 OAS 设备上逐个切换选定角色，复用单账号导出流程。账号来源继续支持「本任务账号表」「勾选配置实例」「角色名列表」三种方式；来源仅决定账号清单，不会按来源配置切换到其他模拟器。

批量执行不需要启用独立的「账号数据导出」调度器，也不会修改它的下次运行时间；整批重试和下一轮运行由「多账号通用任务」的调度器决定。

账号数据导出使用独立任务入口；需要批量导出时，在「多账号通用任务」中选择「账号数据导出」。

### 进度与异常

批量导出只有成功落盘才记为完成；普通失败按现有轮转机制最多尝试三次，再继续下个账号。只要有失败账号，本轮进度就保留，同日接续且进度未过期时跳过已完成账号、补导失败账号；已记录的成功文件丢失时也会重新导出。全部成功后清理本轮进度，下一轮重新采集最新数据。

连接中断、原生调用超时等状态不确定的故障会进入现有人工接管流程，不继续切号。

若原生采集超时或提示前次导出服务仍在运行，请先检查并重启对应模拟器，再恢复任务，避免旧采集尚未退出时继续切号。

## 单账号验证

先在指定模拟器登录角色，再运行：

```powershell
.\toolkit\python.exe -m dev_tools.yyx_export --config oas2
```

该命令只导出当前登录角色，不执行日常、不切换账号。命令行没有账号上下文，导出文件不写 `oas_identity`。

## 输出文件

```text
config/tasks_config/yyx_exports/yyx_<服务器ID>_<角色ID>.json
```

所有 OAS 配置共用这个目录，不再创建配置名子文件夹。每个角色保留最新一份快照；文件名只用服务器 ID 和角色 ID，不含角色名或导出时间，因此重复导出、角色改名、切换 OAS 配置都覆盖同一文件。角色名保留在 JSON 的 `data.player.name` 中。成功后原子替换，失败保留上一次成功文件。不同服务器或角色 ID 分别保存，文件属于运行数据，不提交到 Git。

例如：`yyx_10090_700721018.json`。手动改动文件名不会改变后续导出的固定名称。旧版配置子目录和带角色名的文件不会自动清理；目标文件尚不存在时，可将旧文件移到统一目录并改为上述名称。

以上是 OAS 导出文件的覆盖规则。导入软件是否更新已有账号，由导入端的识别规则决定；建议按 `data.player.server_id` 与 `data.player.id` 识别同一角色。

外层格式与 YYX 一致：`timestamp`、`version: "2.0.0"`、`data`。`data` 包含：

- `player`：角色身份、区服、等级。
- `currency`：金币、勾玉、体力、寄售券等 22 项资源。
- `heroes`、`hero_equips`、`hero_equip_presets`：式神、御魂及预设。
- `hero_book_shards`：式神 ID、碎片数、整卡数、合成所需碎片数。
- `realm_cards`、`story_tasks`：结界卡与传记任务。

式神稀有度支持 `Unknown/N/R/SR/SSR/SP/UR`。原有 `0..5` 序号保持不变，新增 `6` 对应 `UR`（如妖刀姬·绯夜猎刃）；持有 UR 的账号会完整导出，不会丢弃式神或将其降为 Unknown。未定义的序号和错误类型仍会使快照校验失败。旧版仅支持六种稀有度的 YYX 导入端需要更新后才能识别 UR。

多账号导出还会在 `data` 下附带 `oas_identity`：`{character, svr, account}`，取值是「多账号通用任务」账号表里该账号的角色名、区服和登录账号。下游按这三项身份将快照关联到角色库；配置实例名可能是临时导出配置，因此不再写入身份字段。游戏内真名可能与配置里填的不一致，此时可用这份身份认领。三项身份缺任一项就不写该字段：单账号任务与 `dev_tools.yyx_export` 命令行都没有账号上下文，导出文件与旧版格式保持一致。该字段是对象而非数组，不参与 `data` 各数组组的条数统计。

寄售券保存在 `data.currency.consignment_ticket`，与其他货币同组。它读取游戏货币编号 `900338`（寄售屋购买物品使用），与编号 `900339` 的勾玉券不同；单账号和批量导出都会生成该字段。未持有时为 `0`。原版 YYX 的 21 项货币位置及名称保留，解析旧版采集数据时不虚构寄售券数量；旧 JSON 需要重新导出后才有此字段。

`data.story_tasks` 每条记录包含任务编号 `id`、进度 `progress: {value, max_value}`、所属式神编号 `hero_id` 和从 `1` 开始的章节 `chapter`。式神与章节直接来自游戏 `DATA_STORY` 的 `activityId` 原始顺序，和式神本体、碎片使用相同的类型范围，不再受旧版 `200..600` 编号限制；石长姬等新式神的所有已配置章节均会采集。同一个任务编号属于多位式神时，各条归属分别保留。

传记采集的原始位置记录为 `[任务编号, [当前进度, 目标进度], 式神编号, 章节]`，保留原版 YYX 的前两项；解析器兼容原两项和新四项记录，也允许同一快照混合，缺少归属的旧记录不会猜测或补零。旧 JSON 必须重新导出才会补齐新式神进度和归属。进度达成仅表示任务条件已满足，当前未采集「已解锁」或「已领取奖励」标志。

采集接口缺失或字段类型错误时拒绝保存，不把读取错误默认为空值。导出**不按角色名二次核对切号目标**：切号阶段已用统一的异体字归一化（`瑶/瑤`、`别/別`）确认过，导出再按字面比较只会让这类名字差异挡住整份数据。导出的是当时实际登录的角色，文件名与内容都取自采集结果本身，因此即便切错号也不会覆盖目标角色的文件。导出服务只监听模拟器回环地址，通过当前设备的 ADB 转发访问；正常结束后移除本次转发和临时结果，关闭本次专属服务，不关闭游戏或共享 ADB 服务。

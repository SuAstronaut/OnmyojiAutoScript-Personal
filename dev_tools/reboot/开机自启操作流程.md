# OAS守护进程操作流程

## 概述

OAS守护进程通过 REST API + WebSocket 长连接与 OAS Server 通信（与 OASX 客户端方式一致），实现：
- 系统重启后自动拉起 OAS Server 和指定实例
- 多实例状态实时监控，异常时自动恢复
- 定时重启系统

## 配置文件详解

编辑 `dev_tools\reboot\daemon_config.json`：

```json
{
  "api_host": "127.0.0.1",
  "api_port": 22288,

  "server_auto_start": true,
  "server_startup_timeout": 60,
  "server_restart_on_crash": true,

  "monitor_interval": 30,
  "restart_cooldown": 60,

  "reboot_time": "02:00",
  "reboot_weekday": null,

  "instances": [
    {
      "name": "OAS2",
      "enabled": true,
      "auto_restart": true,
      "max_restart_attempts": 5,
      "restart_cooldown": 60
    }
  ]
}
```

### 全局配置

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `api_host` | string | `"127.0.0.1"` | OAS Server 地址 |
| `api_port` | int | `22288` | OAS Server 端口 |
| `server_auto_start` | bool | `true` | 守护进程启动时是否自动拉起 OAS Server |
| `server_startup_timeout` | int | `60` | 等待 Server 启动的超时时间（秒） |
| `server_restart_on_crash` | bool | `true` | Server 崩溃后是否自动重启 |
| `monitor_interval` | int | `30` | 监控检查间隔（秒） |
| `restart_cooldown` | int | `60` | 实例重启默认冷却时间（秒） |
| `reboot_time` | string/null | `null` | 定时重启时间，格式 `"HH:MM"` |
| `reboot_weekday` | int/null | `null` | 定时重启星期几（0=周一，6=周日，null=每天） |

### 实例配置

`instances` 数组支持两种格式：

**简单格式**（使用默认参数）：
```json
"instances": ["oas1", "oas2"]
```

**详细格式**（每个实例独立配置）：
```json
"instances": [
  {
    "name": "OAS2",
    "enabled": true,
    "auto_restart": true,
    "max_restart_attempts": 5,
    "restart_cooldown": 60
  }
]
```

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `name` | string | — | 实例名称，须与 config 目录下的配置文件名一致 |
| `enabled` | bool | `true` | 是否启用此实例的监控 |
| `auto_restart` | bool | `true` | 实例异常时是否自动重启 |
| `max_restart_attempts` | int | `5` | 连续重启失败上限，达到后暂停自动重启 |
| `restart_cooldown` | int | `60` | 两次重启之间的冷却时间（秒） |

### 配置示例

**三实例全量监控**：
```json
{
  "instances": [
    {"name": "oas1", "enabled": true, "auto_restart": true, "max_restart_attempts": 5},
    {"name": "oas2", "enabled": true, "auto_restart": true, "max_restart_attempts": 5},
    {"name": "oas3", "enabled": true, "auto_restart": true, "max_restart_attempts": 3}
  ],
  "reboot_time": "03:00",
  "reboot_weekday": null
}
```

**仅监控不自动重启**：
```json
{
  "instances": [
    {"name": "oas1", "enabled": true, "auto_restart": false}
  ]
}
```

**混合模式**（部分自动重启，部分仅监控）：
```json
{
  "instances": [
    {"name": "oas1", "enabled": true, "auto_restart": true},
    {"name": "oas2", "enabled": true, "auto_restart": false},
    {"name": "oas3", "enabled": false}
  ]
}
```

## 操作流程

### 一、手动运行与验证

安装开机自启前，务必先手动测试：

```bash
cd dev_tools\reboot
python reboot_daemon.py
```

观察日志输出，确认：
1. OAS Server 成功启动（`OAS Server已就绪`）
2. 所有实例 WebSocket 连接建立（`WebSocket 长连接已建立`）
3. 实例启动成功（状态为 `RUNNING`）

### 二、安装开机自启

#### Windows

1. 双击运行 `install_startup.bat`
2. 脚本会：
   - 在 `%TEMP%` 目录创建 `oas_daemon_start.bat` 启动脚本
   - 将启动脚本注册到 Windows 注册表启动项 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`
3. 重启电脑验证守护进程是否自动运行

#### Linux

1. 执行 `bash install_service.sh`
2. 脚本会创建 systemd 服务并设置开机自启
3. 常用管理命令：

```bash
sudo systemctl start oas-daemon     # 启动
sudo systemctl stop oas-daemon      # 停止
sudo systemctl restart oas-daemon   # 重启
sudo systemctl status oas-daemon    # 查看状态
journalctl -u oas-daemon -f         # 查看日志
```

### 三、卸载开机自启

#### Windows

双击运行 `uninstall_startup.bat`

#### Linux

```bash
sudo systemctl stop oas-daemon
sudo systemctl disable oas-daemon
sudo rm /etc/systemd/system/oas-daemon.service
sudo systemctl daemon-reload
```

## 守护进程工作流程

```
启动
 │
 ▼
自动拉起 OAS Server（GET /test 检测 → 启动子进程 → 等待就绪）
 │
 ▼
启动所有 enabled 实例（WebSocket 发送 "start"，失败回退 REST API）
 │
 ▼
进入监控循环 ──────────────────────────────────────┐
 │                                                │
 ├─ Server 在线？ ──否──> 自动重启 Server         │
 │                    │                           │
 │                   是                           │
 │                    │                           │
 ├─ 为每个实例维护 WebSocket 长连接               │
 │   （断开自动重连）                              │
 │                    │                           │
 ├─ 接收服务端推送的状态更新                       │
 │   {"state": 0-3}                               │
 │                    │                           │
 ├─ 检测异常状态                                   │
 │   INACTIVE / WARNING / UNKNOWN                 │
 │                    │                           │
 ├─ 满足自动重启条件？ ──是──> 重启实例            │
 │   (auto_restart=true, 未达上限, 冷却已过)      │
 │                    │                           │
 └─ 等待 monitor_interval 秒 ────────────────────┘
```

## 自动恢复机制

守护进程在以下场景自动恢复：

| 场景 | 检测方式 | 恢复动作 |
|------|----------|----------|
| OAS Server 崩溃 | `GET /test` 无响应 | 自动重启 Server 子进程 |
| 实例进程挂掉 | WebSocket 推送 `{"state": 0}` (INACTIVE) | 通过 WS/REST 重新启动实例 |
| 实例异常警告 | WebSocket 推送 `{"state": 2}` (WARNING) | 先刷新状态确认，必要时重启 |
| WebSocket 断连 | 连接状态标记为 false | 自动重连 |
| 连续重启失败 | 重启计数达 `max_restart_attempts` | 暂停自动重启，记录日志 |

**重启保护**：
- **冷却时间**：两次重启之间至少间隔 `restart_cooldown` 秒，防止频繁重启
- **次数上限**：连续重启失败达 `max_restart_attempts` 次后暂停，避免无限循环
- **运行恢复**：实例状态恢复正常（RUNNING）后自动重置重启计数

## 定时重启

通过 `reboot_time` 和 `reboot_weekday` 配置：

```json
// 每天凌晨2点重启
"reboot_time": "02:00",
"reboot_weekday": null

// 每周日凌晨3点重启
"reboot_time": "03:00",
"reboot_weekday": 6

// 不定时重启
"reboot_time": null
```

定时重启执行流程：停止所有实例 → 关闭 Server → 等待5秒 → 执行系统重启命令

## 故障排除

### 守护进程未启动

1. 检查 `daemon.log` 日志中的错误信息
2. 确认 Python 环境和依赖库（websockets, schedule, nest-asyncio）已安装
3. Windows: 检查注册表启动项是否正确
4. Linux: 执行 `sudo systemctl status oas-daemon`

### OAS Server 启动失败

1. 检查端口是否被占用：`netstat -ano | findstr 22288`
2. 手动运行 `python server.py` 排查错误
3. 检查 `server_auto_start` 是否为 `true`
4. 增大 `server_startup_timeout`（默认60秒）

### 实例无法启动

1. 确认实例名称与 `config/` 目录下的 `.json` 文件名一致
2. 检查模拟器/设备是否已连接（ADB）
3. 查看 OAS Server 日志中实例启动的错误信息
4. 确认 `enabled` 未设为 `false`

### 自动重启不生效

1. 确认 `auto_restart` 为 `true`
2. 检查是否已达到 `max_restart_attempts` 上限（查看日志）
3. 确认冷却时间已过（`restart_cooldown` 秒）
4. 手动重启守护进程可重置重启计数

### WebSocket 连接失败

1. 确认 OAS Server 已启动且端口正确
2. 检查防火墙是否阻止了 WebSocket 连接
3. 守护进程会自动重连，观察日志中的重连尝试

## 注意事项

1. **实例名称一致性**：`daemon_config.json` 中的 `name` 须与 `config/` 目录下的配置文件名一致（如 `oas1` 对应 `config/oas1.json`）
2. **环境配置**：确保系统已安装 Python 依赖、ADB，模拟器已正确配置
3. **定时重启风险**：定时重启会强制关闭所有实例并重启系统，请避开任务执行高峰期
4. **测试先行**：正式启用开机自启前，务必手动运行验证
5. **配置变更**：修改 `daemon_config.json` 后需重启守护进程才能生效
